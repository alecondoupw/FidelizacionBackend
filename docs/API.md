# API de Fidelización Zontes / Kiden / NIU — v1

Referencia de la API Express (F7-BE-02). Base: `https://<backend>/api/v1` (local: `http://127.0.0.1:4000/api/v1`). Colección de pruebas manuales: [`docs/postman/fidelizacion.postman_collection.json`](postman/fidelizacion.postman_collection.json), generada con `npm run docs:postman`. La prueba `src/docs/postman.test.ts` exige que la colección cubra exactamente las rutas de Express y que cada ejemplo pase su validación. El contrato y las decisiones de negocio viven en el Core (`Zontes-Core/02-Arquitectura/Contrato API v0 - F0.md`).

Todos los ejemplos usan datos sintéticos (dominio `ejemplo.test`).

## Convenciones

| Aspecto       | Regla                                                                                                                                                          |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Formato       | JSON UTF-8, cuerpo ≤ 100 kB. Cuerpos **estrictos**: un campo no documentado → 422                                                                              |
| Fechas        | ISO 8601 en UTC (`…Z`). Los filtros de periodo usan días `AAAA-MM-DD` en hora de Bolivia (America/La_Paz), ambos incluidos                                     |
| Marcas        | `zontes`, `kiden`, `niu`                                                                                                                                       |
| Autenticación | `Authorization: Bearer <ID token de Firebase>`; sin cookies. Integraciones: `X-Api-Key`                                                                        |
| Correlación   | Cada respuesta lleva `X-Request-Id` (se respeta el entrante si cumple `^[A-Za-z0-9._-]{8,64}$`)                                                                |
| Tiempos       | `Server-Timing` con las fases `token`, `perfil` y `total` en milisegundos                                                                                      |
| Límites       | 300 peticiones por minuto e IP (configurable con `LIMITE_POR_MINUTO`); `POST /clientes/registro`: 20 cada 15 min por IP → 429 `RATE_LIMITED` con `Retry-After` |
| Paginación    | `limite` (1–100, 20 por defecto) y `cursor` = valor `siguiente` de la respuesta anterior (`null` al final)                                                     |
| Caché         | Las lecturas de datos personales y reportes responden `Cache-Control: no-store`                                                                                |

### Acceso

| Acceso      | Requisito                                                                |
| ----------- | ------------------------------------------------------------------------ |
| Público     | Ninguno                                                                  |
| Token       | ID token válido con correo verificado; aún sin perfil                    |
| Autenticado | Token + perfil registrado y activo de cualquier rol                      |
| Cliente     | Autenticado con rol `cliente`; sólo ve sus datos y sus marcas vinculadas |
| Admin       | Autenticado con rol `administrador`                                      |
| Clave       | `X-Api-Key` válida de un sistema externo                                 |

### Errores

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Los datos enviados no son válidos.",
    "requestId": "…",
    "details": [{ "campo": "puntos", "mensaje": "Debe ser mayor que cero." }]
  }
}
```

`message` es apto para mostrar y nunca contiene trazas, tokens ni datos personales.

| HTTP | `code`                                                                                                                                                                                                      | Cuándo                                                             |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 400  | `INVALID_JSON`, `BAD_REQUEST`                                                                                                                                                                               | JSON mal formado                                                   |
| 401  | `UNAUTHENTICATED`                                                                                                                                                                                           | Falta el token o la clave, o es inválido, expirado o revocado      |
| 403  | `FORBIDDEN`                                                                                                                                                                                                 | Rol, cuenta desactivada o marca no vinculada                       |
| 403  | `REGISTRATION_REQUIRED`                                                                                                                                                                                     | Cuenta de Firebase sin perfil: completar `POST /clientes/registro` |
| 403  | `EMAIL_NOT_VERIFIED`                                                                                                                                                                                        | Correo sin verificar (registro o tras un cambio de correo)         |
| 404  | `NOT_FOUND`                                                                                                                                                                                                 | Ruta o recurso inexistente; también recursos de otro cliente       |
| 409  | `ALREADY_REGISTERED`, `EMAIL_ALREADY_LINKED`, `EMAIL_IN_USE`, `RULE_EXISTS`, `ALREADY_EXISTS`, `IDEMPOTENCY_CONFLICT`, `INSUFFICIENT_BALANCE`, `OUT_OF_STOCK`, `INVALID_STATE`, `LAST_ADMIN`, `SELF_ACTION` | Conflictos de negocio descritos en cada endpoint                   |
| 413  | `PAYLOAD_TOO_LARGE`                                                                                                                                                                                         | Cuerpo > 100 kB                                                    |
| 422  | `VALIDATION_ERROR`, `CLIENT_NOT_FOUND`, `CLIENT_INACTIVE`, `BRAND_NOT_LINKED`, `NOT_AVAILABLE_YET`, `RANGE_TOO_LARGE`, `TOO_MANY_ROWS`                                                                      | Datos inválidos o imposibles                                       |
| 429  | `RATE_LIMITED`                                                                                                                                                                                              | Límite de peticiones superado                                      |
| 500  | `INTERNAL_ERROR`                                                                                                                                                                                            | Fallo no controlado; se registra con su `requestId`                |
| 503  | `AUTH_NOT_CONFIGURED`                                                                                                                                                                                       | Backend sin proyecto Firebase o integración sin claves             |

## Importación de clientes

Sólo administradores (SRC-06 pp. 1–2, DEC-17). El cuerpo de las dos primeras rutas es el **archivo tal cual** (CSV o XLSX, `Content-Type` del archivo), máximo 5 MB y 5.000 filas, con columnas `nombre` y `correo`/`correo electrónico`/`email` en la primera fila. El CSV acepta `;`, `,` o tabulador, UTF-8 o Windows-1252. Nunca crea cuentas de acceso ni administradores.

| Método y ruta                                             | Acceso | Entrada          | Respuesta                                                                                                                   | Errores propios                                                                             |
| --------------------------------------------------------- | ------ | ---------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `POST /admin/importaciones/vista-previa?marca`            | Admin  | archivo          | `{ marca, resumen, filas: [{ fila, nombre, correo, estado, vinculacion, asociacionesPrevias, motivo }] }` sin escribir nada | 413 `PAYLOAD_TOO_LARGE`; 422 `VALIDATION_ERROR` (columnas, archivo dañado), `TOO_MANY_ROWS` |
| `POST /admin/importaciones?marca&archivo&idImportacion`   | Admin  | el mismo archivo | 201 `{ id, resumen, repetido: false }`; 200 `repetido: true` al repetir `idImportacion`                                     | 409 `IDEMPOTENCY_CONFLICT` (mismo id con otra marca o archivo)                              |
| `GET /admin/importaciones`                                | Admin  | —                | `{ items: [{ id, marca, archivo, creadoEn, expiraEn, estado, resumen }] }` de los últimos 90 días                           | —                                                                                           |
| `GET /admin/importaciones/{id}/reporte?formato=csv\|xlsx` | Admin  | —                | archivo: fila, nombre, correo, resultado, vinculación, marcas previas, motivo                                               | 404 si no existe o venció                                                                   |
| `GET /admin/importados?marca&correo&limite&cursor`        | Admin  | —                | importados **sin cuenta**: `{ items: [{ correo, marcas: [{ marca, nombre, importadoEn }], actualizadoEn }], siguiente }`    | —                                                                                           |

**Estados de fila:** `nuevo` y `nueva_asociacion` (se importan), `ya_importado` y `duplicado_archivo` (duplicados), `conflicto` (ya importado en esa marca con otro nombre: se conserva lo existente), `revision` (correo de una cuenta administrativa o con verificación pendiente) y `error` (falta nombre o correo, o correo inválido). **Vinculación:** `vinculara`/`vinculado` (cuenta de cliente con ese correo: se le añade la marca), `ya_vinculado`, `pendiente` (sin cuenta: se vincula al registrarse y verificar el mismo correo). **Resumen:** `importados`, `vinculados`, `pendientes`, `duplicados`, `conflictos`, `revision`, `errores`; los vinculados pueden estar incluidos entre los importados. El detalle del cliente (`GET /admin/clientes/{uid}`) incluye `importadas: [{ marca, nombre, importadoEn }]`.

## Integración (CRM y facturación)

Preparada y documentada; ningún sistema real está conectado (DEC-13).

| Método y ruta               | Acceso | Entrada                                                                                    | Respuesta                                                                                                                                                                                              | Errores propios                                           |
| --------------------------- | ------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------- |
| `POST /integracion/eventos` | Clave  | `{ idExterno (1–128), evento, marca, correoCliente, vence (AAAA-MM-DD, de hoy a 2 años) }` | 201 `{ resultado: otorgado, puntos, movimientoId, venceEn }` o `{ resultado: sin_puntos, motivo: sin_regla\|regla_inactiva }`; 200 con `repetido: true` al repetir `idExterno`. Origen `api:{sistema}` | 401 clave ausente o inválida; 503 sin claves configuradas |

**Alta de un sistema:** `npm run integracion:clave -- --sistema <nombre>` genera una clave aleatoria y su línea `nombre:sha256`. La clave se entrega al sistema externo por un canal seguro; el servidor sólo guarda el hash en `INTEGRACION_CLAVES` (varias separadas por coma). **Idempotencia:** el sistema envía su propio identificador (número de factura, id del CRM) en `idExterno`; repetirlo no otorga dos veces. **Ejemplo:**

```bash
curl -X POST "$BASE/integracion/eventos" \
  -H "X-Api-Key: $CLAVE" -H "Content-Type: application/json" \
  -d '{"idExterno":"factura-000123","evento":"compra","marca":"zontes","correoCliente":"cliente.zontes@ejemplo.test","vence":"2027-10-04"}'
```
